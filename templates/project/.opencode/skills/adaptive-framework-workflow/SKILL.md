# Flujo de trabajo del framework adaptativo

## Aplica un rigor proporcional

1. Aclara el resultado solicitado y la autorización. Trata las consultas, el
   análisis y las revisiones como tareas de solo lectura, salvo que se autoricen
   cambios.
2. Inspecciona las instrucciones del proyecto, la implementación pertinente,
   las convenciones y las comprobaciones disponibles antes de planificar.
3. Evalúa el riesgo, la incertidumbre, el impacto, el alcance, la urgencia y la
   posibilidad de recuperación. Elige un nivel de rigor Ligero, Estándar o
   Reforzado; la urgencia o llamar «arreglo urgente» a una tarea no reduce por
   sí sola el rigor.
4. Resuelve las incertidumbres importantes a partir de evidencias del proyecto.
   Pregunta antes de continuar cuando una decisión pendiente afecte de forma
   significativa al alcance, la arquitectura, los datos o la seguridad.

## Planifica y ejecuta

1. Usa el mecanismo de seguimiento existente en el proyecto. Si el trabajo es
   sustancial y no hay un mecanismo, propón un documento de trabajo breve antes
   de crearlo.
2. Define tareas acotadas, con criterios de aceptación y solo dependencias
   reales. No crees tareas para trabajos triviales.
3. Ejecuta únicamente la tarea autorizada. Conserva el trabajo ajeno y evita
   solapar cambios.
4. Reevalúa el plan si aparecen evidencias que cambien de forma significativa el
   riesgo, el alcance, las dependencias o el resultado esperado.

## Valida y entrega

1. Ejecuta las comprobaciones nativas más pequeñas que sean pertinentes y recoge
   sus resultados reales.
2. No afirmes que las comprobaciones no ejecutadas han pasado. Indica los
   fallos, las comprobaciones no disponibles y los riesgos residuales.
3. Marca el trabajo como completado solo cuando existan evidencias de que cumple
   sus criterios de aceptación. Actualiza el registro o documento de trabajo
   aprobado.
4. En trabajos por fases, detente al terminar la tarea actual. Informa de la
   siguiente tarea desbloqueada sin iniciarla; pausa si hace falta una
   autorización o decisión.

La configuración y las instrucciones de OpenCode orientan el comportamiento,
pero no garantizan por sí solas su cumplimiento técnico. Respeta los permisos
efectivos y las políticas del proyecto.
